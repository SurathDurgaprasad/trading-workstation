Phase 21 — Decision Intelligence Engine

A Label, Not an Order

A new decision_engine/ package combines the last persisted scanner evidence and an open-position flag into one of BUY / WATCH / AVOID / EXIT / NO_ACTION — a deterministic classification, evidence-backed and reproducible by construction, with an optional AI layer that can only narrate the label, never choose it. No order is placed, and nothing in this package can reach one.

02

Safety framing, stated first

A Decision is a label (BUY/WATCH/AVOID/EXIT/NO_ACTION) plus recorded evidence and rationale — not an order, not an authorization. decision_engine/ imports nothing from paper/, nothing from any broker adapter, and calls no order-placing code path (none exists anywhere in this repository to call). Converting a label into an actual paper trade remains a separate, unchanged, entirely manual step: the existing paper/paper-live commands are untouched by this phase. The CLI prints this explicitly on every run: "DECISION -- LABEL ONLY, NOT AN ORDER (no trade is placed by this command)".

03

Scope

In scope: a deterministic BUY/WATCH/AVOID/EXIT/NO_ACTION classification from a market_intelligence.CandidateScore and an open-position flag; full evidence recording (scanner + research + risk context) on every Decision; SQLite persistence; an optional, never-blocking AI narrative; a decide CLI subcommand that reads the latest persisted scanner/research evidence.

Explicitly out of scope: position sizing, capital allocation, stop/target/quantity (roadmap Phase 22 — see §09's limitations), account-level circuit breakers (kill switch/drawdown/daily-loss — risk/engine.py's unchanged job at actual order-approval time, a separate downstream stage per the roadmap's own pipeline diagram), any change to market_intelligence/, research/, risk/, paper/, or any existing agent.

04

What was built

decision_engine/ models.py DecisionLabel, RiskContext, DecisionNarrative, Decision -- Pydantic, evidence-enforcing (see §06) config.py DecisionConfig -- one behavioral knob, versioned (see §05) rules.py classify() -- the ONLY place the label is decided; pure function, no I/O, no LLM engine.py make_decision(), narrate_decision() -- orchestration + optional AI narration store.py DecisionStore -- SQLite, same convention as paper/store.py, market_intelligence/store.py, research/store.py

main.py decide --symbol X [--scanner-db P] [--research-db P] [--paper-db P] [--no-narrative] [--db P] wires it up: reads the latest scan report and research report for the symbol from their own existing SQLite stores (no re-scan, no re-research triggered), optionally checks a paper-trading database for an open position, calls make_decision, prints the label + rationale + evidence-availability + narrative, and persists every decision to data/decisions.db.

05

The classification rule, and why it has no magic number

Already holding this symbol? ├─ yes, no scanner data -> NO_ACTION ├─ yes, composite_score <= 0 -> EXIT └─ yes, composite_score > 0 -> WATCH (keep holding, no exit signal) Not holding: ├─ no scanner data -> NO_ACTION ├─ composite, trend, AND momentum all positive -> BUY ├─ composite positive, but trend/momentum don't agree -> WATCH └─ composite not positive -> AVOID

Phase 19's own report states its scanner factor weights are "equal-weighted by default, not tuned" — no historical study has validated what a specific composite_score value means "good enough to buy." Rather than invent a numeric cutoff this project has no evidence for, BUY requires sign agreement across three independent factors (composite, trend, momentum all positive) — meaningful regardless of the composite score's uncalibrated scale, and a materially more conservative bar than trusting one blended number's exact magnitude. DecisionConfig.require_corroboration_for_buy (default True) is the one behavioral knob this phase exposes, versioned via the same sha256-of-config pattern RiskConfig/ScannerConfig already use.

06

Evidence requirement: how it's structural

Roadmap acceptance criterion: "No recommendation without recorded evidence." Enforced by a Pydantic model_validator on Decision itself, not by convention: any label other than NO_ACTION requires scanner_evidence to be present, or construction raises ValueError — a Decision that violates this cannot exist, regardless of how it's constructed or by which future caller. "Decision is reproducible": classify() is a pure function of typed inputs with no randomness, I/O, or LLM call — proven directly by a dedicated test (test_classify_is_a_pure_function_of_its_inputs). "Decision version is stored": every Decision.config_version records DecisionConfig.version_id().

07

What was reused, not rewritten

  • market_intelligence.models.CandidateScore (Phase 19) — the sole scanner-evidence type; not duplicated or re-derived.
  • research.models.ResearchReport (Phase 20) — recorded as supporting context on every Decision (see §09's limitation on what drives the label).
  • agents.analyst.invoke_structured — the exact retrying, schema-validating LLM call agents/signal_explainer.py and research/summarizer.py already use. One new AgentRole ("decision_narrator") added to core/config.py, the same way "research_summarizer" was added before it.
  • The "AI must never block" posture from research.summarizer.build_research_report/main.py's _try_ai_explain — make_decision's narrative step is a direct structural analog, including the same deferred-import discipline (decide --no-narrative never pays the langchain_core import cost).
  • paper/store.py's / market_intelligence/store.py's / research/store.py's persistence convention — DecisionStore mirrors all three exactly.
  • risk.config.RiskConfig.version_id's sha256 pattern — reused verbatim for DecisionConfig.version_id.

decision_engine/ does not import paper/ or risk/engine.py. The CLI's optional --paper-db open-position lookup is wired at the main.py layer only, keeping the package itself testable and usable with no paper-trading database at all.

08

A bug found by self-audit, fixed

classify() could return WATCH with no scanner evidence, which Decision's own validator then rejected FIXED

Re-reading rules.py adversarially (per the phase's own "check empty inputs, check partial data" self-audit step) surfaced a real crash: when a position is already held but no current scanner data exists for it, the first draft returned WATCH with reasons but no candidate. make_decision then constructed Decision(label=WATCH, scanner_evidence=None, ...) — which Decision's own §06 validator immediately rejects with ValueError, since WATCH is not NO_ACTION. make_decision("AAPL", candidate=None, risk_context=RiskContext(has_open_position=True)) would have raised instead of returning a Decision. Fixed by returning NO_ACTION in that branch instead — consistent with the not-holding branch, which already treated "no evidence" as NO_ACTION regardless of position status. A dedicated regression test (test_make_decision_does_not_crash_when_holding_with_no_scanner_evidence) proves this end-to-end through make_decision, not just classify() in isolation, so a future change to either function can't silently reintroduce the same crash.

Tests

41 new tests (pytest-collected count, including parametrized cases): 12 in test_decision_engine_rules.py (every branch of the classification tree including the fixed holding/no-evidence case, corroboration on/off, determinism), 11 in test_decision_engine_models.py (3 direct, plus 2 parametrized tests x 4 labels each covering the evidence-requirement validator's accept/reject behavior for every non-NO_ACTION label; config version-id sensitivity), 8 in test_decision_engine_engine.py (narrative success/unavailable/opt-out, symbol normalization, the crash regression, structural proof of DecisionNarrative's field set), 6 in test_decision_engine_store.py (save/get round-trip, per-symbol scoping, ordering/limit, reconnect persistence, an explicit assertion that no update method exists), and 4 CLI tests (arg parsing, one end-to-end run composing real ScanHistoryStore/ResearchStore data through to a BUY decision, one proving missing-evidence is reported honestly rather than silently). No real network or Ollama call anywhere in the unit suite.

10

Known limitations, stated honestly

  • MarketContext and ResearchEvidence do not yet drive the label. Both are recorded on every Decision as supporting context (and ResearchReport.ai_summary's text is passed into the AI narrative prompt), but classify()'s deterministic rule currently reads only CandidateScore and the open-position flag. Extending the rule to weigh technical/research evidence directly is a natural future refinement, deliberately deferred until there's a concrete, evidence-based way to combine them rather than another fabricated weighting.
  • No automatic composition with `scan`/`research`. decide reads whatever was last persisted by separate scan/research runs; it does not trigger a fresh scan or research fetch itself. A stale or missing evidence store is reported honestly ("none found"), never silently substituted.
  • Risk context is deliberately narrow (open-position + loss-streak count only) — account-level circuit breakers remain entirely risk/engine.py's job at actual order-approval time, unreachable from and untouched by this phase.
  • No position sizing, capital, or price levels anywhere in this phase — by design; that separation is roadmap Phase 22's job.
