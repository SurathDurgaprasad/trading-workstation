Regime filter hypothesis test — Phase 9

The regime edge Phase 8 found doesn't survive being made causal

Three small, pre-specified, real-time-computable regime filters were laid over the frozen Phase 8 control strategy — never modifying it. None improved risk-adjusted performance out-of-sample, none survived realistic costs, and reconstructing Phase 8's own regime breakdown causally (using only information available at each trade's entry, instead of a full quarter's retrospective return) shows the original "strong-uptrend is great" finding was largely an artifact of a look-ahead-tainted, retrospective label. This is Phase 9's central, mechanistic finding: not just that the filters failed, but a specific, well-evidenced reason why.

0 changes to strategy/baseline.py, risk/, or paper execution Control reproduced exactly on all 12 symbols 3 candidates tested, 0 confirmed 257/258 tests passing (1 pre-existing, unrelated) Classification: C
Bottom line

Classification C — the regime-filter hypothesis is rejected. None of the 3 pre-specified candidates (broad-trend SMA200, low-volatility-regime, and their combination) produced a full-period, cost-surviving, out-of-sample improvement over the unmodified control. Every candidate's 95% bootstrap CI on mean R-multiple overlaps the control's and straddles zero — none is statistically distinguishable from control or from no edge.

The deeper finding: re-computing Phase 8's own regime breakdown causally (trailing 63-bar return known at the moment of entry, not a full quarter's start-to-end return applied retroactively to every trade inside it) collapses the effect Phase 8 reported. Trades causally labeled "strong uptrend" showed mean R = −0.105, barely different from "sideways" trades' −0.258 — nothing like Phase 8's retrospective +0.30R vs −0.30R gap. The original regime signal was not fully available at the time a trade would have needed to act on it.

1Control reproduction (spec: "run the control first")

The exact Phase 8 TrendMomentumBaseline, run unmodified on the same 12-symbol universe. To keep the control and candidates on identical data, two harmless extra columns (sma_200, atr_median_100) were added to each symbol's indicator series before any backtest — the control strategy reads only its own named columns and ignores the extras.

Exact match, all 12 symbols

Every control metric (trade count, net PnL, win rate, expectancy R) on the augmented series matched Phase 8's original numbers exactly — 218 pooled trades, net PnL −$7,547.20. This confirms the added columns have zero effect on the control and that this phase's comparison starts from a verified-identical baseline.

2Exact candidate hypotheses

Exactly 3 candidates — within spec's 3-5 limit — each implemented as a FilteredStrategy (strategy/regime_filters.py) that calls the UNCHANGED control strategy first and can only SUPPRESS its signal, never alter or invent one. Not registered in strategy/registry.py — deliberately unreachable from the CLI, a research artifact only.

Candidate A — broad_trend_sma200:   allow signal only if close > SMA(200)
Candidate B — low_volatility_regime: allow signal only if ATR14 <= rolling_median(ATR14, 100 bars)
Candidate C — trend_and_low_vol:    A AND B

3Rationale (stated before any result was inspected)

CandidateRationale
A — SMA200Phase 8 found strong-uptrend quarters profitable, sideways ones not; SMA20/50 is a short-horizon crossover that can flip inside a broader non-trending regime. Price-vs-SMA200 is one of the most standard, non-cherry-picked "primary trend" checks in technical analysis.
B — ATR-vs-rolling-medianPhase 8 found low-volatility quarters profitable (+0.34R), high-volatility ones not (−0.28R). A causal, adaptive, per-symbol proxy built only from the ATR column the strategy already computes.
C — combinationPhase 8's cross-tab suggested trend and volatility are each independently informative; directly tests requiring both — spec's own explicit candidate concept #6.

Explicitly considered and excluded

  • ADX / trend-strength. Spec gated this on "if already supported cleanly" — market/indicators.py has no ADX implementation. Building a new, nontrivial indicator (Wilder's ADX has several easy-to-get-wrong smoothing steps) purely to test one candidate, under this phase's explicit small-N constraint, was judged not worth the added correctness risk versus the two well-established, already-partially-supported concepts (long SMA, ATR) chosen instead.
  • Higher-timeframe (weekly) trend confirmation. Correctly aligning a resampled weekly bar to a daily decision without leaking the still-in-progress current week is a genuine causality trap — exactly the class of bug spec §"THE FILTER MUST NOT CHEAT" warns about. Rather than risk a subtle look-ahead bug under this phase's time budget, it was excluded and is named here as a candidate for a future phase, not silently dropped.

4Causality / look-ahead analysis

Both regime columns are pure rolling-window functions of price/ATR history up to and including each row's own bar — the identical causal-by-construction pattern already audited in Phase 8's look-ahead tests. Verified three ways, all in tests/test_regime_filters.py (11 new tests, all passing):

  • Structural: sma_200/atr_median_100 computed on a truncated series match the full series' value at the same row exactly.
  • Signal-level: mutating every bar strictly after bar T (price, ATR, and the regime columns themselves) never changes the filter's allow/suppress decision at bar T.
  • Composition: a filtered signal is either None or byte-identical to what the unchanged inner strategy itself produced — the filter cannot invent or alter a signal, only suppress it.

Real-time implementability, explicitly answered for each candidate: yes for all three — every input (trailing close prices, trailing ATR values) is knowable at the exact bar the signal is generated, with no dependency on anything not yet observed.

9Out-of-sample — the most important result (spec's own framing)

No candidate improves out-of-sample

Control's OOS mean R (+0.061) is actually the best of the four variants. Candidate A's OOS dollar PnL is slightly worse than control's despite a marginally higher R (a function of differing trade counts, not a real edge). Candidates B and C are worse on both PnL and R out-of-sample, and their OOS trade counts (19 and 14) are too thin to support any claim either way — exactly the "trade count collapsed, classify as inconclusive on this cut" scenario spec §"STATISTICAL DISCIPLINE" anticipates. Candidate A's validation-period improvement (+601.70 vs control's −1,428.19) does not carry through to out-of-sample — a textbook example of why OOS, not validation, is the decisive cut.

10Causal regime analysis — the central finding

Phase 8 classified whole ~63-bar quarters by their FULL start-to-end return and applied that label to every trade inside the quarter — including trades entered near the quarter's start, before the quarter's eventual direction was knowable. Phase 9 reclassifies each trade using only its own TRAILING 63-bar return, known at the exact moment of entry — causal by construction, exactly matching spec's explicit warning not to "turn the Phase 8 retrospective regime labels into a trading signal."

The gap shrinks from 0.595R to 0.153R once the label is made causal — both regimes are now negative, and the difference between them is small next to the pooled standard deviation of R (≈1.65, from Phase 8's distribution analysis). This is the mechanistic explanation for why all three real-time-implementable candidates failed: they were built to approximate a signal (trend/volatility regime) whose Phase 8 incarnation partly depended on information — the quarter's own future return — that would not have been available at the time a live system needed to decide.

11Drawdown analysis

Pooled maximum consecutive losing trades is identical across all four variants (6) — the RiskEngine's consecutive-loss hard limit (Phase 4.5, unchanged) caps this the same way regardless of which signals reach it. No candidate materially changed the loss-streak profile; the filters reduce trade count but not the shape of losing runs.

13Trade-count impact

Trade count fell from 218 (control) to 182 (A, −16%), 127 (B, −42%), and 105 (C, −52%). Counterintuitively, at the per-symbol level a filter can occasionally INCREASE a symbol's trade count relative to control (INFY.NS under candidate A: 18 trades vs. control's 8) — a real, correctly-understood consequence of the single-position-per-symbol constraint: suppressing an early signal can free the account to take a later signal that control's own RiskEngine would otherwise have vetoed as POSITION_ALREADY_OPEN. The formal per-signal guarantee (a filtered signal is either absent or byte-identical to the inner strategy's own signal at that exact bar) still holds and is tested — it is aggregate trade count, a path-dependent downstream effect, that is not guaranteed to only decrease.

18Final classification

C — hypothesis rejected

None of the 3 pre-specified, causal, real-time-implementable regime filters produced a full-period, cost-surviving, out-of-sample-confirmed, statistically-distinguishable-from-control improvement. The one candidate with any positive signal (A, at zero cost and in the validation window) failed to carry that improvement into out-of-sample or under realistic costs. The causal regime-breakdown analysis (§10) supplies a specific, mechanistic reason: Phase 8's retrospective regime observation was itself partly a look-ahead artifact, not a fully tradeable signal.

19What this does NOT prove

  • This does not prove no regime filter could ever help. It tests exactly 3 pre-specified, simply-motivated candidates — not the space of all possible regime constructions.
  • This does not prove the causal-vs-retrospective gap fully explains Phase 8's finding. It is the most direct, tested explanation available and is consistent with all the data gathered, but other factors (sample noise, symbol mix) were not separately isolated.
  • This does not prove the underlying TrendMomentumBaseline strategy is unfixable. It only tests whether THIS family of regime gates rescues it — Phase 8's own verdict on the ungated strategy stands independently.
  • Candidate A's zero-cost and validation-period improvements are not evidence of a real edge. They did not survive the two tests spec explicitly weights most heavily — realistic costs and out-of-sample — and are reported for completeness, not as a partial success.
  • None of this was tested on data or symbols chosen after seeing results. The universe, period, and candidate definitions were fixed before any candidate backtest ran (verified: the control reproduction in §1 used data fetched/cached before any candidate code existed in this conversation).

20Recommendation for Phase 10

Do not carry any of the 3 candidates forward for confirmation — none cleared the bar spec itself set (OOS improvement, cost survival, statistical distinguishability, symbol breadth). The one substantive, reusable output of this phase is methodological rather than a trading candidate: the causal-vs-retrospective regime-labeling gap (§10) is a generally applicable lesson for any future regime-conditioning work on this platform, and should be treated as a standing constraint — any future "does regime X help" hypothesis must be specified and tested causally from the start, the way this phase's FilteredStrategy pattern now makes straightforward to do correctly. Absent a new, differently-motivated hypothesis, the appropriate next step is the same one Phase 8 already recommended: treat the platform's proven engineering correctness as the deliverable, and apply this same rigor to any future strategy candidate before considering live deployment of any kind.
