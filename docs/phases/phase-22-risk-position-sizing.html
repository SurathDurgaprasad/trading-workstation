Phase 22 — Dynamic Risk & Position Sizing

A Bridge, Not a Second Risk Engine

Reconciliation before code: risk/config.py, risk/engine.py, and risk/account.py already implement everything the roadmap's Phase 22 feature list asks for — dynamic, never-hardcoded capital, risk-per-trade, a daily-loss limit, exposure limits, and position sizing computed fresh from current equity on every call. None of that was rebuilt. The actual gap: RiskEngine.evaluate needs a fully-formed Signal with concrete stop/target prices, and Phase 21's Decision deliberately carries only a label. This phase is exactly that bridge, and nothing more.

03

Scope

In scope: risk/sizing.py — a small, purely additive module that constructs the Signal a BUY Decision implies (using the exact, already-established ATR-based stop/target convention), then hands it to the unmodified RiskEngine.evaluate; a size CLI subcommand that previews the result against caller-specified capital.

Explicitly out of scope: any new risk/sizing methodology, any change to risk/engine.py/risk/config.py/risk/account.py, any order placement (real or paper), any new persisted history (this is a stateless preview, not a new audit record — the roadmap does not ask for one here, unlike Phase 21's decisions).

04

What was built

risk/sizing.py SizingUnavailableError raised for a non-BUY label, missing/non-positive ATR, mismatched symbols, or a degenerate stop build_signal_for_buy() Decision + MarketContext -> Signal, using strategy.baseline's OWN STOP_ATR_MULTIPLIER (1.5) / TARGET_RISK_REWARD (2.0) -- not new math size_decision() build_signal_for_buy() -> RiskEngine(config).evaluate(signal, account) -- zero new risk logic, pure composition

main.py size --symbol X reads the latest persisted Decision (Phase 21's DecisionStore), fetches a fresh MarketContext (market.context.get_market_context, unchanged since Phase 2), builds an Account from CLI-supplied capital, and prints the resulting RiskDecision — approved/quantity/risk amount/exposure/veto reasons — using the identical 8 risk-config flags (--risk-per-trade, --max-daily-loss, etc.) already defined on the backtest subcommand, for consistency.

05

Safety framing

risk/sizing.py imports nothing from paper/ and calls no order-placing code path (none exists anywhere in this repository). The CLI prints "POSITION SIZING PREVIEW -- NOT AN ORDER (no real or paper trade is placed)" on every run. This command answers "what WOULD the existing, unchanged risk engine do with this decision, given this capital" — it does not act on that answer. Converting an approved preview into an actual paper trade remains the existing, entirely separate paper/paper-live path.

06

Self-audit: adversarial edge cases checked

  • Extreme ATR producing a negative stop price. Signal has no gt=0 constraint on stop_price, and RiskEngine.evaluate would not crash on one (the arithmetic stays well-defined) — but a negative stop is nonsensical for a real instrument and would silently pass structurally_valid. Checked directly rather than assumed safe: build_signal_for_buy now explicitly refuses to build a Signal when the computed stop_price is not positive, with a regression test (test_build_signal_for_buy_refuses_a_degenerate_negative_stop) reproducing the exact ATR/price combination that triggers it.
  • A BUY Decision with scanner_evidence=None. Verified rather than trusted: Phase 21's own Decision model_validator makes this impossible to construct in the first place (checked by re-reading that validator, not by re-implementing the check here). build_signal_for_buy does not read scanner_evidence at all — every price input comes from MarketContext — so this scenario was moot even before confirming it's unreachable.
  • Zero/negative capital. Account's own initial_capital: float = Field(gt=0) constraint (Phase 3, unchanged) already rejects this at construction with a Pydantic ValidationError (a ValueError subclass, already in main.py's _CONTROLLED_ERRORS) — no new handling needed or added.
  • Mismatched symbols (a Decision for one symbol paired with a MarketContext for another). Explicitly checked and refused with a clear SizingUnavailableError, with a regression test.
  • A non-BUY label reaching size_decision. Every one of WATCH/AVOID/EXIT/NO_ACTION is tested individually (parametrized) to confirm SizingUnavailableError, not a silent no-op or a crash.

A pre-existing test file was overwritten, caught by a test-count mismatch FIXED

The very first draft of this phase's tests used Write to create tests/test_risk_sizing.py without reading it first — a file of that exact name already existed from the original Phase 0-13 commit, containing 12 real, unrelated tests of RiskEngine's own position-sizing formula (fractional-risk flooring, capital-bounded quantity caps, exposure-driven rejection with sizing still reported, etc.). The overwrite was caught not by inspection but by a test-count discrepancy: a full regression run showed 691 passed where 703 was expected from the new tests added. Rather than accept the lower number, the gap was traced directly (pytest --collect-only on the suspect file matched the missing count exactly) back to the overwritten file. Fixed by restoring the original tests/test_risk_sizing.py from main unchanged, and moving this phase's own new tests to a distinctly-named tests/test_risk_sizing_bridge.py. Full regression re-confirmed at 703 passed after the fix. Recorded here as a reminder that an unexpected test-count delta is itself a signal worth chasing down, not rounding away.

Tests

17 new tests: 13 in test_risk_sizing_bridge.py (exact stop/target formula verification against strategy.baseline's own constants, every non-BUY label rejected, missing/zero/degenerate ATR rejected, mismatched symbols rejected, an ample-capital approval, an insufficient-capital rejection, and a direct equality check proving size_decision's output is byte-for-byte identical to calling the unmodified RiskEngine directly with the same Signal -- proof no parallel sizing methodology was introduced), and 4 CLI tests (arg parsing mirroring the backtest risk-flag set, missing-decision handling, one end-to-end run through a real DecisionStore BUY decision to a real, unmodified-RiskEngine-produced approval). 08

Known limitations, stated honestly

  • BUY only. WATCH/AVOID/NO_ACTION correctly have nothing to size. EXIT (closing an existing position) is deliberately out of scope here — that is an instruction to close, a paper/engine.py concern entirely separate from RiskEngine.evaluate's new-entry sizing question, not a Phase 22 gap.
  • No new persistence. A sizing preview is not saved anywhere; re-running size against fresh market data can produce a different Signal/RiskDecision for the same underlying Decision, since ATR/price move with the market. This is intentional (a preview reflects "right now"), not a reproducibility gap in Decision itself (which remains immutable and unchanged).
  • The ATR-based stop/target convention is Phase 3's, unvalidated for this purpose. Reusing it here (rather than inventing a second convention) was the correct call per this project's own anti-duplication discipline, but it inherits whatever uncertainty already exists about that convention's own effectiveness (Phase 8's validation study found no evidence of a durable edge for the strategy that originated it).
