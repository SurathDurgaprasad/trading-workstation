What was already there: Phase 18's unused router

The prior operational audit (pre-Phase-28) had already flagged, and Phase 18's own final audit had already documented as a deliberate non-fix: market_data.provider.UnifiedMarketDataFacade, market_data.contracts.SnapshotAdapter, market_data.adapters.{yahoo,dhan,mock}, and market_data.models.InstrumentSnapshot/MarketSnapshot -- exactly the roadmap's own "Provider Router / Live Provider (Dhan) / Historical Provider (Yahoo) / Canonical Market Model / Source Health" diagram -- were built in Phase 18 and never consumed by anything downstream (Phase 19's scanner and everything after it went straight to MarketDataProvider.fetch_ohlcv instead). Phase 31's real job turned out to be smaller than initially planned: wire the ALREADY-BUILT, ALREADY-TESTED router into the intelligence pipeline, not build a new one.

03

Reconciliation: why not a Dhan-as-MarketDataProvider swap

The obvious-sounding approach -- "make Dhan a MarketDataProvider so scan/decide can use it directly" -- does not fit the actual interfaces. MarketDataProvider.fetch_ohlcv(symbol, period, interval) is a one-shot BATCH historical request (Yahoo's natural shape); Dhan's live data is a STREAMING subscribe/poll interface (live.contracts.MarketDataSource) with no concept of "give me a year of daily bars synchronously." Indicators (SMA/RSI/MACD/ATR) need that historical warm-up window, which no live feed in this project can supply. The two are genuinely different shapes, not just different implementations of the same one -- Phase 18's own SnapshotAdapter already resolved this correctly: a THIRD, narrower question ("what is the current state of this instrument right now") that both shapes can answer, via StreamingSnapshotAdapter (Dhan) and YahooSnapshotAdapter (Yahoo). This phase composes on top of that existing answer rather than re-solving an already-solved problem differently.

04

Scope

In scope: MarketContext.data_source/data_status/data_freshness_seconds (reusing the existing OHLCVBar.source/status and SourceHealth types, never inventing new labels); an optional live_snapshot_provider parameter on get_market_context that overlays price/timestamp/provenance from any SnapshotAdapter when healthy, and degrades silently to the Yahoo historical value otherwise; a real, credential-gated --live-source dhan CLI flag on size/predict reusing Phase 15/16's exact credential-loading and Phase 18's exact, unmodified adapter.

Explicitly out of scope: wiring a live overlay into scan/shadow-run (bulk, multi-symbol loops -- a live WebSocket subscription per symbol in a batch scan is a materially bigger, riskier undertaking than a single decision's price check, and was not attempted this phase); any claim that this has been exercised against a real Dhan connection (§08); decide (does not build a MarketContext at all today -- out of this phase's scope to add).

05

What was built

get_market_context(symbol, live_snapshot_provider=None) 1. ALWAYS: fetch Yahoo historical OHLCV, compute indicators (unchanged) -> context.data_source = bar.source.value (e.g. "YAHOO") -> context.data_status = bar.status.value (e.g. "HISTORICAL") 2. IF live_snapshot_provider given: snapshot = live_snapshot_provider.get_snapshot(symbol) IF snapshot.health.status == HEALTHY and snapshot.latest_bar is not None: -> override price / as_of / data_source / data_status / data_freshness_seconds ELSE (stale / disconnected / error / exception): -> silently keep the Yahoo historical context (logged, never raised)

--live-source dhan (on size/predict) constructs the live provider via main._build_live_snapshot_provider, which calls the SAME load_dhan_credentials() and DhanInstrumentMap.download() Phase 15/16's paper-live --source dhan already uses, and the SAME, unmodified Phase 18 market_data.adapters.dhan.build_dhan_adapter. Missing credentials raise the existing DhanCredentialsMissingError, already in main.py's _CONTROLLED_ERRORS -- a clean one-line message, not a traceback.

08

Safety

  • No new order-placement or broker-mutation code path anywhere -- --live-source dhan only ever calls get_snapshot() (read-only), the same as the pre-existing, unmodified StreamingSnapshotAdapter Phase 18 already built and tested.
  • A broken/unavailable live source degrades to the existing, safe Yahoo historical path -- never blocks or crashes size/predict.
  • tests/test_dhan_no_real_orders.py / tests/test_broker.py: 12/12 passed before and after this phase's changes.
09

Known limitations, stated honestly

  • A real Dhan live overlay has not been exercised. This environment has no configured DHAN_CLIENT_ID/DHAN_ACCESS_TOKEN -- the credential-gate itself is real-service-verified (a clean error), the actual live-quote path is not (§06).
  • scan/shadow-run remain Yahoo-only. A live overlay across a whole watchlist loop is architecturally heavier (one WebSocket subscription lifecycle across many symbols) and was deliberately not attempted this phase -- a real, named follow-on, not an oversight.
  • decide still does not build a MarketContext at all. Unchanged from before this phase -- its label comes from scanner+research evidence only, never price.
