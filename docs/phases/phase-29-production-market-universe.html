02

Reconciliation: why not NIFTY 50

The operator's Phase 29 spec asks for "index-based universe architecture" and a "liquid-stock starter universe." Phase 18 already left nifty50/nifty100/nifty200/nifty500 as recognized-but-unimplemented modes, explicitly reasoned: index membership changes over time via periodic rebalancing, and this project integrates no live, verifiable index-membership source. Implementing mode: nifty50 backed by a bundled static list would mean shipping a list under an official-sounding name this project cannot verify is current or accurate — a direct violation of the project's own "never claim real-service verification from something that isn't" discipline (roadmap §25/§26).

This phase instead delivers everything else the spec asked for — validation, exchange metadata, instrument identifiers, a bounded starter list — without that specific overclaim. The starter list ships as market_data/watchlists/starter_nse.yaml, explicitly labeled in its own header as "NOT an official NIFTY 50/100/500 constituent list," loadable via the EXISTING --watchlist-file flag every scan/research/decide/shadow-run/schedule command already has — no new CLI surface needed for that part.

03

Scope

In scope: symbol validation (reject a comma-joined or internally-whitespace-containing entry with a clear message), exchange_for_symbol (NSE/BSE/OTHER from the Yahoo suffix convention), InstrumentMetadata + MarketUniverse.describe() (best-effort Dhan security ID enrichment, never blocking), a new read-only universe CLI command, and a committed 15-symbol starter watchlist.

Explicitly out of scope: mode: nifty50/100/200/500 (see §02), any new market-data source, any change to scan/research/decide/shadow-run/schedule's own logic.

04

What was built

python main.py universe --symbols RELIANCE.NS,AAPL --with-dhan-ids SYMBOL EXCHANGE DHAN SECURITY ID DHAN DISPLAY NAME RELIANCE.NS NSE 2885 Reliance Industries AAPL OTHER not found

market_data.universe.MarketUniverse.describe(instrument_map=None) is the library function behind it — every symbol always gets an exchange (a pure, offline derivation), and a Dhan security ID/display name ONLY if a DhanInstrumentMap is supplied and recognizes the symbol. --with-dhan-ids triggers exactly one call to the ALREADY-EXISTING, credential-free DhanInstrumentMap.download() (Phase 15) — no new download mechanism, no new dependency.

05

Bug found and fixed

`from_watchlist` accepted a comma-joined or whitespace-containing single symbol silently

Found by re-reading the existing Phase 18 validation adversarially: passing "AAPL,MSFT" as ONE list element (a realistic paste/typo error — e.g. forgetting to .split(',') a comma-joined string before wrapping it in a list) previously produced a single bogus symbol that only failed much later, opaquely, at the Yahoo fetch stage inside scan/shadow-run's own per-symbol try/except (silently logged as one more "excluded" or "FAILED" entry, easy to miss in a large watchlist run). Fixed by rejecting any symbol containing a comma or internal whitespace at from_watchlist construction time, with a message naming the actual mistake. Regression tests added; confirmed the existing leading/trailing-whitespace normalization (already handled by .strip()) still passes.

Safety

  • universe is entirely read-only metadata description — no order, no recommendation, no persistence, no risk/decision logic anywhere in this phase.
  • --with-dhan-ids reuses the EXISTING, already-tested, credential-free DhanInstrumentMap.download() — no new network mechanism, no credentials read or required.
  • tests/test_dhan_no_real_orders.py / tests/test_broker.py / tests/test_dhan_instruments.py: all passed before and after this phase's changes.
10

Known limitations, stated honestly

  • No index-membership mode implemented. Deliberate — see §02. nifty50/100/200/500 remain recognized-but-unimplemented, exactly as Phase 18 left them.
  • The starter watchlist is illustrative, not authoritative. 15 well-known, long-established NSE large-caps chosen for stability of their ticker symbols, not sourced from any live index feed — stated explicitly in the file's own header.
  • Company "name" metadata is Dhan's own SEM_CUSTOM_SYMBOL field (e.g. "Reliance Industries"), not a separately verified corporate name source — adequate for display, not for any legal/compliance use.
