02

Reconciliation: six agents, one gap

The roadmap's own Phase 25 text is short: "Build specialized AI research agents. Possible agents: Market Analyst, Technical Analyst, News Analyst, Sector Analyst, Risk Critic, Decision Reviewer. Agents must not independently execute trades." Reading agents/*.py and graph.py in full before writing anything found:

Roadmap-suggested agentStatusWhere it already lives
Technical AnalystEXISTSagents/technical_agent.py, part of the original Phase 1/2 analyze pipeline (graph.py)
Risk CriticEXISTS (adjacent)agents/risk_agent.py (risk assessment narration) + agents/critic_agent.py (devil's-advocate critique) in the same pipeline
News AnalystEXISTSresearch/summarizer.py's research_summarizer role (Phase 20) already narrates news evidence
Sector AnalystEXISTSSame research_summarizer call already includes sector classification in its evidence bundle
Market AnalystDEFERREDNo existing single-symbol agent maps to this; a whole-watchlist AI overview has little use without a place to show it, which is Phase 26's job (Live Market Decision Dashboard) — premature here
Decision ReviewerBUILT THIS PHASEagents/decision_reviewer.py (new)

The existing five-agent analyze pipeline (market_context_agent → technical_agent/risk_agent/critic_agent → debate_agent → supervisor_agent) is a separate, coexisting system: it operates on raw market.context.MarketContext for the standalone Phase 1/2 analyze command, producing an LLM opinion (schemas.decision.TradingDecision) with no deterministic backing. This session's new pipeline (Phase 18-24) is deterministic-first: decision_engine.rules.classify decides, and AI only narrates or reviews afterward. Building a second Technical Analyst or Risk Critic for the new pipeline, when the underlying market data and indicators are identical, would have been pure duplication.

03

Scope

In scope: agents/decision_reviewer.py — an independent, adversarial AI second opinion on an already-fixed decision_engine.models.Decision, for any label (not just BUY); a review CLI subcommand.

Explicitly out of scope: a Market Analyst agent (deferred to Phase 26, see §02), any new Technical Analyst/Risk Critic/News Analyst/Sector Analyst (all reconciled as already-existing, see §02), and any order, real or paper — agents/decision_reviewer.py imports nothing from paper/ or any broker adapter.

04

What was built

agents/decision_reviewer.py review_decision(decision) -> DecisionReview -- an independent, adversarial critique of an already-fixed label decision_engine/models.py DecisionReview -- concerns / supporting_points / overall_assessment no field can hold a label, price, or action

main.py review --symbol X reads the latest persisted Decision (same DecisionStore lookup pattern size/predict already use), calls check_ollama_availability() up front for a clean error if the LLM isn't reachable (matching analyze's own pre-flight check — unlike decide/research, there is no meaningful evidence-only fallback for a command whose entire purpose is the AI critique), and prints the review's concerns, supporting points, and overall assessment. review_decision works for any DecisionLabel, not just BUY — reviewing "why NO_ACTION" is just as meaningful as reviewing a BUY, and it needs no price levels the way risk.sizing/predictions.tracker's BUY-only bridges do.

05

What was reused, not rewritten

  • agents.analyst.invoke_structured — the exact retrying, schema-validating LLM call every prior AI feature in this pipeline already uses (research_summarizer, decision_narrator).
  • decision_engine.store.DecisionStore — read unchanged, the same "look up the latest Decision" composition size/predict already established.
  • The "cannot change the decision" type-level guarantee — DecisionReview follows the identical pattern as DecisionNarrative (Phase 21), ResearchSummary (Phase 20), and SignalExplanation (Phase 4.5): a narrow field set with no room for a revised label, price, or action.
  • The check_ollama_availability() pre-flight pattern from main.py's run() (the analyze command) — the correct precedent for a command with no non-AI fallback, distinct from decide/research's never-blocking optional-AI posture.
06

Self-audit: adversarial edge cases checked

  • Missing research evidence. review_decision's prompt construction has an explicit fallback string for both "no news evidence" and "no AI research summary" — verified with a test that captures the actual prompt text sent to the (fake) LLM, not just that the call succeeds.
  • A non-BUY, evidence-free decision. Deliberately tested against a NO_ACTION decision (scanner_evidence=None, the one label that structurally allows it) to confirm review_decision has no BUY-only assumption baked in anywhere, unlike Phase 22/23's price-level bridges.
  • Import cost for other commands. agents/decision_reviewer.py and llm.provider are only imported inside run_review_command's own function body -- main.py's module-level imports are untouched, so no other command pays anything for this phase's addition.
07

Tests

8 new tests (verified via pytest --collect-only): 3 in test_decision_reviewer.py (structural proof of DecisionReview's field set, the missing-evidence prompt fallback, the NO_ACTION/no-scanner-evidence case), 1 added to the existing test_decision_engine_models.py (the same structural field-set proof at the model level), and 4 CLI tests (arg parsing, missing-decision handling, one end-to-end run through a real DecisionStore to a faked LLM response). No real network or Ollama call anywhere in the unit suite. Full regression: 782 passed, 0 failed.

08

Safety

  • agents/decision_reviewer.py imports nothing from paper/ or any broker adapter.
  • DecisionReview cannot express a label, price, or action by construction (§05) — the same residual free-text risk every prior narration schema in this project already carries (a model could mention something recommendation-shaped in prose despite the prompt's explicit instruction not to), not a new gap.
  • The CLI prints "AI CRITIQUE ONLY, CANNOT CHANGE THE LABEL" on every run.
09

Known limitations, stated honestly

  • Market Analyst is deliberately deferred, not built. See §02 -- a whole-watchlist AI overview has no natural home to be read from until Phase 26's dashboard exists.
  • No persistence. A review is printed, not stored -- matching Phase 22's size preview posture, not Phase 21/23's audit-history posture. Reviews are cheap to regenerate on demand; nothing currently needs to compare reviews over time.
  • The two agent ecosystems remain separate. This phase does not merge or bridge the original analyze/graph.py pipeline with the new scanner/research/decision pipeline -- they continue to coexist, each serving its own command.
