02

Scope

In scope: a new /intelligence/<symbol> decision-detail page (decision history with confidence/rationale, full scanner-evidence breakdown, research evidence with news/sector/AI summary, prediction history with entry/stop/target/outcome/return), a link to it from the candidates table, and a real confidence-calibration section added to the existing learning snapshot. One small, symmetric store addition: PredictionStore.list_predictions_for_symbol, matching the exact convention DecisionStore.list_decisions_for_symbol/ResearchStore.list_reports_for_symbol already established.

Explicitly out of scope: a live, on-demand position-sizing calculator on this page (would require either a page-load market-data fetch -- violating the existing "no fetch, no LLM, no write on GET" dashboard discipline -- or a POST-triggered form, a reasonable follow-on not attempted this phase); a dedicated separate "audit trail" page (the decision-history table on this same page already serves that purpose for a single symbol; a cross-symbol audit view is a natural but separate future addition).

03

What was built

GET /intelligence/<symbol> decisions = DecisionStore.list_decisions_for_symbol(symbol) [existing] research = ResearchStore.list_reports_for_symbol(symbol) [existing] predictions = PredictionStore.list_predictions_for_symbol(symbol) [NEW, same convention] exchange = market_data.universe.exchange_for_symbol(symbol) [existing, Phase 29] -> DECISION section: latest label/confidence/explanation/rationale + full history table -> SCANNER EVIDENCE section: composite/trend/momentum/breakout/relative-strength/sector-strength + explanation -> RESEARCH EVIDENCE section: sector, AI summary, news list -> PREDICTION HISTORY section: entry/stop/target/outcome/return per prediction

Every getter returns an empty list/None (never fabricates) when its database or symbol has no data yet, matching dashboard/intelligence.py's existing convention exactly.

06

Safety

  • Read-only throughout -- no POST route, no store write, no order of any kind on this page.
  • Every symbol value is HTML-escaped before rendering (verified directly: a URL-encoded <script> payload renders as inert escaped text, confirmed by a dedicated test).
  • All store lookups use parameterized queries (the existing store convention) -- no SQL injection surface regardless of symbol content.
  • tests/test_dhan_no_real_orders.py / tests/test_broker.py: 12/12 passed before and after this phase's changes.
07

Known limitations, stated honestly

  • No live sizing calculator on this page. Entry/stop/target come only from an ALREADY-recorded prediction (if one exists) -- a symbol with a BUY decision but no predict run yet shows no price levels here, even though size/predict could compute them live via the CLI.
  • No cross-symbol audit trail view. This page is per-symbol; a "show me every decision system-wide, filterable and sortable" view was not attempted this phase.
  • Market regime is not shown on this page. Phase 33's regime command remains CLI-only -- adding it here would need either a fresh benchmark fetch (violating the no-fetch-on-GET rule) or persisting regime reports, neither attempted this phase.
