03

Architecture decision, stated before coding

Reading the existing code first (per the phase execution protocol) found the "fragmentation" framing in the roadmap draft to be partly inaccurate: market.data_provider.MarketDataProvider (one-shot historical fetch) and live.contracts.MarketDataSource (streaming subscribe/next_bar) are already clean, @runtime_checkable Protocols sharing one canonical OHLCVBar type. What is genuinely missing is a THIRD question neither answers: "what is the current state of this instrument, right now, regardless of whether the source is streaming or historical?" market_data/ answers exactly that question, as a layer on top — it does not replace, duplicate, or modify either existing protocol.

04

What was built

market_data/ contracts.py SnapshotAdapter Protocol -- one method: get_snapshot(symbol) models.py InstrumentSnapshot, MarketSnapshot -- wrap the EXISTING OHLCVBar, never redefine it quality.py SourceHealth -- reuses live.freshness.FreshnessPolicy's own math, not a second formula universe.py MarketUniverse -- watchlist mode only; nifty50/100/200/500 recognized, explicitly rejected as unimplemented provider.py UnifiedMarketDataFacade -- ties one adapter + one universe together adapters/ _streaming.py StreamingSnapshotAdapter -- shared drain/cache/lazy-subscribe logic mock.py build_mock_adapter() -- wraps MockMarketDataSource, unmodified dhan.py build_dhan_adapter() -- wraps DhanMarketDataSource, unmodified yahoo.py YahooSnapshotAdapter -- wraps YahooFinanceProvider, unmodified

Every adapter turns a source-specific failure (no data, disconnected, provider error) into an explicit SourceHealth value on the returned snapshot — never a raised exception a caller scanning many symbols would need to catch per-symbol, and never a fabricated bar.

05

What was reused, not rewritten

  • OHLCVBar (market/data_provider.py) — the sole bar representation; InstrumentSnapshot wraps it, never redefines OHLC fields.
  • live.freshness.FreshnessPolicy — SourceHealth.from_bar_timestamp delegates to it directly, including its existing naive/aware datetime normalization (proven necessary again here: Yahoo/mock bars are naive, real Dhan bars are UTC-aware since the Phase 16 fix).
  • MockMarketDataSource, DhanMarketDataSource, YahooFinanceProvider — wrapped by adapters, zero lines of any of the three modified.
  • live.contracts.MarketDataSource's NO_NEW_BAR/FeedDisconnectedError contract — the streaming adapter's drain loop respects it exactly as the existing pipeline does.

08

Known limitations, stated honestly

  • StreamingSnapshotAdapter.get_snapshot() can block up to the underlying source's own next_bar_timeout_seconds on its last drain iteration when nothing new has arrived — a real characteristic of the existing poll-with-timeout next_bar() contract, which this phase does not change. Scanning many symbols through one streaming adapter in a tight loop would be slow; not a problem this foundation phase needed to solve, since nothing yet calls it that way.
  • build_mock_adapter() wraps a single-symbol mock replay; asking it for a snapshot of a symbol outside that replay correctly (not silently) reports NO_DATA, but there is no multi-symbol mock source yet.
  • No persistence layer for MarketSnapshot was added — the roadmap's "market state can be persisted" criterion is satisfied in the sense that the model is a plain, serializable dataclass; actually writing it to storage is left to whichever future phase has a concrete need.
  • MarketUniverse is watchlist-only; index-membership modes remain unimplemented by design.
09

Final reconciliation audit, before merge

A fresh audit (not from memory) covering architecture, model correctness, universe edge cases, dependency hygiene, and safety. Two real, demonstrated issues were found and fixed; everything else audited was already correct.

1. Snapshot freshness could falsely report healthy data for a future-dated bar FIXED

SourceHealth.from_bar_timestamp delegated entirely to FreshnessPolicy.check(), which treats a negative age (a bar timestamped in the future relative to now) as trivially "fresh" — a negative number is always ≤ any positive threshold. This is exactly the blind spot that let the original Dhan IST/UTC bug (~5.5 hours in the future) go undetected before Phase 16 found and fixed it at the source. Fixed with a configurable future-tolerance guard (default 300s) directly in market_data/quality.py — large enough to correctly still classify the real, observed Dhan clock skew (~2 minutes, from Phase 16 live testing) as HEALTHY, small enough to catch a genuine anomaly of that original bug's magnitude as ERROR. live/freshness.py itself was not touched.

2. Watchlist symbols were not deduplicated or case-normalized FIXED

A duplicate or differently-cased entry ("RELIANCE" and "reliance") was treated as two distinct symbols, inflating len(universe) and causing UnifiedMarketDataFacade.get_market_snapshot() to redundantly re-fetch the same instrument. Fixed: MarketUniverse.from_watchlist now strips, uppercases (matching YahooFinanceProvider's own existing internal normalization), and deduplicates while preserving first-occurrence order; __contains__ normalizes its query the same way.
