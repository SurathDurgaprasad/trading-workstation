Phase 34 — Decision Confidence & Calibration

A Real Number, Not a Median-Split Proxy

Decisions get a genuine confidence field: the fraction of independent scanner factors (trend/momentum/breakout/relative-strength/sector-strength) that agree with the decision's own direction — deterministic, explainable, and structurally incapable of coming from an LLM. Learning's own calibration report gains a second, real view alongside the old composite-score-median proxy it explicitly flagged as "not literal probability calibration" since Phase 24.

02

Scope

In scope: decision_engine.confidence.compute_confidence (deterministic factor-agreement score), Decision.confidence/confidence_explanation (new, optional, backward-compatible fields), a second, real calibration view in learn's report (fixed LOW/MEDIUM/HIGH bands against the real score, alongside the existing composite-median proxy kept for continuity), and CLI/dashboard display everywhere a decision is already shown.

Explicitly out of scope: removing or replacing the legacy composite-median calibration (kept, now clearly labeled "legacy proxy" rather than deleted -- not enough evidence yet to know which view is more useful in practice); any confidence-adjusted position sizing or decision logic (confidence is informational only in this phase, exactly like every other AI-adjacent field in this project -- it explains, it does not decide).

03

What was built

decision_engine.confidence.compute_confidence(candidate) -> ConfidenceBreakdown direction = sign(candidate.composite_score) # +1, -1, or 0 (flat -> confidence 0.0) for each of {trend, momentum, breakout, relative_strength, sector_strength}_score: None -> unavailable (excluded from both numerator and denominator) == 0 -> neutral (excluded from both) same sign as direction -> agreeing opposite sign -> disagreeing score = agreeing / (agreeing + disagreeing) # 0.0 if nothing to compare Decision.confidence = score (persisted, never LLM-derived) Decision.confidence_explanation = "N of M available factor(s) agree (...); disagreeing: (...)."

Wired into make_decision() unconditionally -- computed for EVERY decision with a candidate (BUY, WATCH, AVOID, and EXIT alike; a confident AVOID means many factors agree it's declining, not just BUY decisions), never gated on whether an AI narrative was also requested. Surfaced in decide's CLI output, the /intelligence dashboard's candidate table, and learn's new "Phase 34: real decision_engine.confidence score" calibration section.

06

Safety

  • Confidence is purely informational -- it changes no label, no position size, no order. decision_engine.rules.classify's own logic is completely untouched.
  • Structurally incapable of LLM influence: compute_confidence takes only a CandidateScore, has no LLM/network dependency of any kind, and is called before the optional narrative step even runs.
  • tests/test_dhan_no_real_orders.py / tests/test_broker.py: 12/12 passed before and after this phase's changes.
07

Known limitations, stated honestly

  • Not yet probability-calibrated in the statistical sense. The real calibration report shows win rate per confidence bucket, but with the small sample sizes any personal-use system will have for a long while, "HIGH confidence predictions win more often" is not yet a statistically established claim -- see the roadmap's own later "Profitability Evidence Framework" phase for the rigor this deserves.
  • Confidence is a factor-agreement count, not a magnitude-weighted score. Five factors barely agreeing (each just above zero) scores identically to five factors agreeing strongly -- a deliberate simplicity choice (explainable, no fabricated weighting), not an oversight.
  • Confidence does not (yet) feed back into sizing or the decision label. Purely informational this phase, matching the roadmap's own "no opaque AI output should silently control labels" framing extended here to "no automatic score should silently control sizing either, without a separate, deliberate architectural decision."
