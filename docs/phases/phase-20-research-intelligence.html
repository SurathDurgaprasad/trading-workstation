Phase 20 — Research Intelligence

Real Evidence First, AI Narration Second

A new research/ package (the name freed by renaming the Phase 10/11 package to quant_research/) fetches real Yahoo Finance news and sector classification for a symbol, then optionally asks a local LLM to synthesize — never invent — a plain-language summary with confidence and stated unknowns. The first roadmap phase to touch an LLM outside the existing analyze/explanation paths, and it reuses that exact infrastructure rather than building a second one.

02

The research/ rename, done deliberately now

The Phase 18 and 19 reports both flagged the same fact and deferred acting on it: the existing research/ package (Phase 10's alpha_features.py, Phase 11's volume_signal.py — frozen, research-only quant feature studies, never imported by any live/paper/strategy/risk path) shares a name with the roadmap's own target package for news/company/sector/macro research and AI reasoning. Phase 18's report said explicitly: "that rename... remains a deliberate, separate task for whenever Phase 20 actually needs the name." This phase needs the name for real, so the rename happens here, as its own first, isolated step: git mv research quant_research, two import updates (tests/test_alpha_features.py, tests/test_volume_signal.py — the only two files anywhere that imported from it), one docstring path update (market_intelligence/config.py), content of both files otherwise byte-for-byte unchanged. The Phase 10/11 HTML reports under docs/phases/ are left untouched, per this project's own stated preservation policy (docs/PHASE_HISTORY.md: "copied byte-for-byte... not re-typed") — they remain historically accurate for what was true when they were written.

03

Scope

In scope: real news collection (Yahoo Finance, via the already-integrated yfinance dependency), real sector/industry classification (same source), an optional AI summary layer with a structurally-enforced Evidence/Source/Timestamp/Confidence/Unknowns shape, SQLite persistence, a research CLI subcommand.

Explicitly out of scope: no buy/sell/BUY-WATCH-AVOID output (roadmap Phase 21), no entry/target/stop/quantity, no macro research, no fabricated "Company Events" data (see §10), no changes to market/, market_data/, market_intelligence/, strategy/, risk/, paper/, or any existing agent.

04

What was built

research/ errors.py ResearchDataError -- same role as market.data_provider.MarketDataError models.py NewsItem, SectorInfo, ResearchSummary, ResearchReport -- Pydantic, matches paper/*.py's persisted-model convention news.py NewsProvider Protocol + YahooNewsProvider -- wraps yfinance Ticker.news sector.py SectorInfoProvider Protocol + YahooSectorInfoProvider + build_sector_map() summarizer.py summarize_research(), build_research_report() -- the only LLM entry point store.py ResearchStore -- SQLite, same convention as paper/store.py and market_intelligence/store.py

main.py research --symbol X [--news-limit N] [--no-ai-summary] [--db PATH] wires it up: fetches news + sector (always), attempts an AI summary unless skipped (never blocking), prints the report, persists every run to data/research.db.

build_sector_map(symbols, provider) closes a limitation the Phase 19 report stated explicitly: "no sector taxonomy is looked up automatically from any source." market_intelligence.scanner.run_scan's sector_map parameter is unchanged — this only supplies a real value for it, when a caller chooses to wire the two packages together (not done automatically, to keep the packages independently testable and usable).

05

Evidence requirement: how it's structural, not a prompt

The roadmap's critical requirement: "Every AI conclusion must include: Evidence, Source, Timestamp, Confidence, Unknowns." This is enforced by construction, the same way schemas/explanation.py's SignalExplanation already enforces "the LLM cannot resize a position": ResearchSummary (the LLM's only return type) has exactly three fields — summary, confidence, unknowns — and no field capable of holding a price, action, or fact not traceable to the evidence block in the prompt. Evidence/Source/Timestamp live on NewsItem (source, published_at) and SectorInfo, populated by deterministic code before the LLM is ever called; the LLM never originates evidence, only narrates what ResearchReport.news/.sector already contain. The one honestly-stated residual risk: summary is free text, and nothing stops the model from mentioning something recommendation-shaped in prose despite the prompt's explicit instruction not to — the identical, already-accepted risk posture SignalExplanation.narrative has carried since Phase 4.5. This phase does not claim a stronger guarantee than the one this project already relies on elsewhere.

06

What was reused, not rewritten

  • agents.analyst.invoke_structured — the exact retrying, schema-validating LLM call already used by agents/signal_explainer.py; not a second structured-output mechanism.
  • llm.provider.check_ollama_availability/get_chat_model — unchanged; one new AgentRole ("research_summarizer") added to core/config.py's existing role/temperature mechanism, the same way "signal_explainer" was added before it.
  • yfinance — already a direct project dependency (market.data_provider.YahooFinanceProvider); no new credential, no new external service, no scraping of a site this project doesn't already rely on.
  • The "AI must never block" posture from main.py's _try_ai_explain — build_research_report's AI-summary branch is a direct structural analog: broad exception handling, a logged reason, real evidence returned regardless.
  • paper/store.py's / market_intelligence/store.py's persistence convention — ResearchStore mirrors both exactly.

market_intelligence.scanner.CandidateScore.explanation can optionally be passed into summarize_research/build_research_report as candidate_explanation — reusing Phase 19's own already-explainable text rather than re-deriving a technical description, without research/ importing anything from market_intelligence/ beyond that plain list[str] (a deliberately loose coupling: research/ stays fully usable, and fully testable, with no scanner involved at all).

08

A bug found by my own testing, fixed

research/summarizer.py imported langchain_core unconditionally, even for --no-ai-summary FIXED

main.py's own long-standing convention (documented at its own top, re: the backtest subcommand) is that a command not needing Ollama/LangGraph must never pay their ~15-20s import cost. The first draft of research/summarizer.py imported agents.analyst/llm.provider at module top level; because main.py research --no-ai-summary still imports research.summarizer for build_research_report's evidence-gathering logic, every research invocation paid that cost regardless of the flag — measured directly: the CLI test suite's -k research subset ran in 36s before the fix. Fixed by deferring both imports inside the functions that actually need them (summarize_research, and only the AI-summary branch of build_research_report), matching the deferred-import pattern main.py's _try_ai_explain already uses. Re-measured after the fix: 0.24s.

10

Safety

  • Zero imports of paper/, risk/, or any broker adapter anywhere in research/.
  • No credentials used or referenced — yfinance calls are unauthenticated public endpoints, identical to every other use of that dependency in this project.
  • ResearchSummary cannot express a buy/sell/quantity/price action by construction (see §05).
  • No hidden network or LLM calls in the unit test suite (60 of 65 new tests use fakes; the 5 CLI tests use fake provider classes, matching Phase 19's established CLI-test convention).
11

Known limitations, stated honestly

  • Company Events not implemented. yfinance's earnings-date API requires lxml, not currently a project dependency; adding it for one secondary field, or building a more fragile scrape, was not justified this phase. Documented here rather than silently omitted.
  • "Sector Analysis" is classification, not aggregation. This phase supplies a real per-symbol sector/industry label and a helper to build a symbol->sector map; broader sector-rotation/breadth analysis remains market_intelligence's job (already partially covered by Phase 19's sector-strength scoring once a real map is supplied).
  • News coverage depends entirely on Yahoo's own feed for a given symbol -- not a curated, deduplicated, cross-source aggregation. A thinly-covered or delisted symbol may return few or zero items; build_research_report handles that as real, valid evidence (possibly none), never as an error.
  • The AI summary's free-text field carries the same residual risk SignalExplanation.narrative already does (see §05) -- not a new gap introduced by this phase.
  • No automatic wiring between research/ and market_intelligence/ exists yet (e.g. calling build_sector_map automatically before a scan) -- left for whichever future phase actually needs that composition, per this project's own "don't build ahead of a real need" discipline.
